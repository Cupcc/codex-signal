# Codex Signal 验收计划

本计划服务于用户要求的 agents team 流程。先冻结 B 会话伙伴岛规格，再实现可运行应用，最后用独立证据验收。当前结论为 ISSUES，产品代码及运行证据尚未进入本次审查。

## 判定与证据

每个用例记录 VERIFIED、NOT VERIFIED 或 INCONCLUSIVE。NOT VERIFIED 表示缺少证明或观察到失败。INCONCLUSIVE 表示测试环境不能判断。两者都不能视为通过。

证据分四层。

| 层级 | 证据 | 能证明什么 |
|---|---|---|
| 状态 | 固定事件回放与断言输出 | 事件输入产生正确的公开状态和提醒决策 |
| 应用 | 实际构建产物、交互录屏或截图、进程输出 | 原生窗口和真实操作遵守状态契约 |
| 接入 | 隔离测试会话产生的原始事件与显示状态 | 指定 Codex 版本和指定来源确实产生该事件 |
| 声音 | 队列日志、实际系统语音播放或录音 | 语音策略、播放次序和最终音频可用 |

静态 HTML、单元测试和模拟事件均不能替代真实 Codex 接入证据。日志中“准备播放”不能证明扬声器已出声。窗口截图不能证明键盘、跳转和焦点行为。

## 本轮最小交付闭环

1. 提供本地可构建的原生 macOS 应用和确定性事件回放入口。
2. 事件经统一状态模型形成会话列表，并在一行内展开详情。
3. 主动作打开对应来源。精确定位不可用时明确显示降级结果。
4. 点击查看只改变查看状态。审批或提问须由后续事件解除。
5. 语音服务消费同一批去重事件，并支持暂停。声音失败不阻止事件接收。
6. 真实事件接入按来源和事件种类逐项记录能力。未证实的能力显示未连接或未知。
7. 保留用户已有 notify 配置。安装或启用 Hooks 的步骤作为独立、可审查操作。

本轮可以交付“本地原生版本，指定接入能力已验证”。只有真实桌面和 CLI 的必要用例全部通过，才可以宣称“桌面与 CLI 完整接入”。

## P0 状态验收矩阵

| ID | 输入或操作 | 可观察结果 | 最低证据 |
|---|---|---|---|
| S01 | 同项目分别产生桌面和 CLI 会话 | 显示两行，来源和稳定标识不同 | 状态回放 |
| S02 | 同来源同项目产生两个会话 | 显示两行，主动作目标不混用 | 状态回放及目标检查 |
| S03 | 同一审批事件连续投递三次 | 仅一个待处理项，仅一次提醒决策 | 状态回放 |
| S04 | 审批等待后点击查看 | 行仍存在，待处理仍为 1，显示已查看或仍待确认 | 状态回放及应用操作 |
| S05 | S04 后收到请求解除或恢复运行 | 同一行更新为运行状态，待处理变为 0 | 状态回放 |
| S06 | 新回合提问后收到旧回合结束 | 新回合仍等待回答，计数保持 | 乱序事件回放 |
| S07 | 两个项目同时结束 | 两条待查看，待处理为 0，不互相覆盖 | 状态回放 |
| S08 | 主动中断、普通工具错误、连接断开 | 分别显示已停止、保留当前生命周期、状态不可用。均不显示成功 | 状态回放 |
| S09 | 应用重启并恢复历史快照 | 保留仍待处理项，不补播历史结束 | 使用临时数据目录重启 |
| S10 | 父会话仍运行，普通子任务结束 | 不产生普通完成播报。子任务请求介入时仍可提醒 | 状态回放 |
| S11 | 非法 JSON、缺少会话标识、未知事件种类 | 接收端不崩溃，不改变已有会话；给出可诊断结果 | 边界输入测试 |
| S12 | 再次投递已消费事件或中断写入后重试 | 状态不重复，事件不会造成无限重播 | 进程级回放 |

## P0 原生界面验收矩阵

| ID | 输入或操作 | 可观察结果 | 最低证据 |
|---|---|---|---|
| U01 | 打开三会话样本 | 纵向列表，每行 56px 蓝色角色，只展开一行，详情和主动作在该行 | 原生截图 |
| U02 | 当前展开审批行时新增问题 | 当前行、焦点、滚动位置保持；计数更新；新行可发现 | 原生交互前后证据 |
| U03 | 收起后重新打开 | 审批与提问优先，按等待时间排列，再显示错误、结束、运行 | 原生操作及状态快照 |
| U04 | 切换全部与待处理 | 结束不计入待处理；已查看审批仍计入；不可见选中项按规则迁移 | 原生操作 |
| U05 | 20 个会话和长标题 | 列表可滚动，工具栏与计数可见，主动作可达；标题不挤掉按钮 | 原生截图及滚动 |
| U06 | 空列表、空筛选、断连 | 分别显示对应说明和有效入口，不出现假的运行中或完成 | 原生截图 |
| U07 | 事件在其他应用输入期间到达 | 不夺取输入焦点，不切走应用 | 实际输入与事件注入 |
| U08 | 用户主动展开后使用方向键、Return、Escape | 分别选择会话、执行主动作、收起；没有隐藏自动审批 | 原生键盘操作 |
| U09 | 有刘海和无刘海屏幕几何 | 内容避开系统读取的安全区域，面板不超出可用区域 | 几何测试；可用设备上的原生截图 |
| U10 | 用户点击主动作但目标定位不可用 | 显示打开应用或打开终端的降级提示，不宣称已定位具体会话 | 原生降级场景 |

U09 的几何测试只能证明布局算法，不能证明没有接入的真实显示器表现。外接屏、全屏、放大文字和辅助功能应分别记录设备与设置。没有对应设备或权限时列为 INCONCLUSIVE。

## P0 真实接入验收矩阵

| ID | 来源与场景 | 可观察结果 | 最低证据 |
|---|---|---|---|
| I01 | CLI 完成一个隔离任务 | 当前版本实际结束事件更新正确会话，不把结束描述为任务成功 | 版本、脱敏原始输入、原生画面 |
| I02 | CLI 审批、提问、主动中断、终止错误 | 每种已支持事件有独立证据。未支持项明确列出 | 每种事件各一份证据 |
| I03 | 桌面版完成及需要用户介入 | 确认事件来自该桌面会话，不是另启 app-server 的测试会话 | 版本、原始输入、稳定会话标识 |
| I04 | Hook 输入来自 stdin，notify 输入来自参数 | 两个入口各自正确解析，处理失败不改变审批决定 | 接收器进程级测试 |
| I05 | 接收端不可用或声音失败 | Codex 继续运行，接收器有有界退出行为，stdout 不输出审批决定 | 隔离失败注入 |
| I06 | 接入安装前后 | 原 notify 的命令及参数完整保留。没有修改信任记录绕过审核 | 脱敏差异与原接收器回归测试 |

只读取配置且没有安装接入时，I06 可记录“配置未修改”。这不能证明安装后兼容性。真实测试使用独立临时配置目录与无敏感数据的会话。不要把用户现有会话作为破坏性测试对象。

## P0 声音验收矩阵

| ID | 输入或操作 | 可观察结果 | 最低证据 |
|---|---|---|---|
| A01 | 审批、提问、结束分别到达 | 播放对应中文短句，不朗读命令、代码、私有路径或完整正文 | 文案断言及一次真实语音 |
| A02 | 两个交接事件连续到达 | 首条立即播放，后续逐条顺序播放，任何时刻最多一个播放活动 | 播放回调断言及实际队列日志 |
| A03 | 暂停声音期间收到事件，再恢复 | 保留视觉状态，不补播过期完成 | 应用操作及队列断言 |
| A04 | 锁屏或已配置勿扰时段收到事件 | 静音；解锁后保留仍待处理数量 | 系统事件或明确标注的模拟输入 |
| A05 | 系统声音不存在或播放失败 | 使用明确降级或无声结果，事件处理继续 | 故障注入 |

声音选择、语速和音量属于设计要求。若本轮只提供固定中文声音与暂停，应在产品规格列为剩余工作，不能以设置界面占位替代实现。

## 建议 fixtures

fixture 记录业务事件和期望公开状态，期望值独立编写。每条事件包含来源、会话、回合、请求、发生时间、事件种类和目标。来源适配层保留输入原样样本，核心层使用标准事件。

| fixture 名称建议 | 覆盖 |

| same-project-two-sessions | S01、S02、U01 |

| stale-completion-after-question | S06 |
| simultaneous-completions | S07、A02 |
| stop-error-disconnect | S08、U06 |
| restart-with-unresolved-request | S09、S12、A03 |
| child-completion-and-attention | S10 |

自动化优先测试完整输入和输出。不要断言私有函数调用次序。计时策略使用注入时钟，进程退出和真实语音另外做集成测试。

## 建议验证入口

以下为待实现接口建议，当前仓库尚没有这些命令，不可写成已执行。

- `swift test` 运行事件、状态、排序、持久化与声音策略测试。
- `scripts/verify.sh` 在临时数据目录运行构建、测试、接收器故障场景和事件回放，非通过时返回非零退出码。
- `scripts/run-demo.sh` 启动真实原生应用并加载固定样本。界面持续显示演示模式。
- 应用提供仅在测试参数开启时可用的状态快照输出，用于核对会话、选中项、计数和播放队列。快照不得包含完整会话正文。

验收报告记录构建产物路径、执行命令、时间、用例 ID、结果和证据路径。实现者的总结不能替代独立验收者运行记录。

## 依据与尚缺内容

规则依据为 [产品与交互设计](../../design/DESIGN.md) 的第 3、5、6、7、8、9、11、12 节。交互基线为 [B 会话伙伴岛](../../design/ui/02-inbox.html) 与 [关键场景](../../design/ui/07-inbox-flows.html)。[现有验证记录](../../design/VERIFICATION.md) 明确声明交付仍是静态画板。

Prove It Works 原则要求检查真实产物，因此本计划把状态、应用、接入和声音证据分开。Test Behavior, Not Implementation 原则要求测试用户可见结果，因此矩阵使用会话身份、计数、跳转结果和播放行为作为断言。

本次只完成计划，不宣称任何产品用例已通过。真实事件覆盖、设备覆盖、语音实际出声与导航准确性仍须执行验证。
