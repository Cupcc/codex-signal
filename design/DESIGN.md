# Codex Signal · 产品与交互设计

版本：1.2 · 2026-11-13 · 已选 B「会话伙伴岛」，新增 Claude Code 小螃蟹

## 1. 设计北极星

**在需要你的那一刻，让正确的任务找到你。**

Signal 是以 [CodeIsland](https://github.com/wxtsky/CodeIsland) 为基础，面向 Codex（桌面版与 CLI）和 Claude Code 的通知体验设计。保留原项目的灵动岛、会话信息和状态小角色，重点改善人机交接与中文系统语音。它把任务的交接状态放在屏幕顶部，同时用简短系统语音提醒。用户应在两秒内知道：哪个项目、为什么需要我、从哪里继续。

**用户最新选定 B「会话伙伴岛」，明确不选 C。** 以纵向会话列表、每行圆润小玩偶和选中行就地展开为主线。A、C 保留为历史对照。

## 3. 一个对象，一项主动作

任何一次展开都必须指定一个会话。项目是分组，真正的定位与状态以会话和回合为准。

**唯一主动作：查看会话。**

它优先定位到准确的 Codex 对话、终端窗口或 tmux pane。定位失败时显示可读的项目与来源，并提供“打开 Codex”或“打开终端”降级入口；不得把“应用已打开”表述成“已定位会话”。

“稍后提醒”“暂停语音”“全部待查看”是次级动作。首版不在浮层里放“始终允许”、自动审批或任意命令执行。用户在 Codex 原有界面查看上下文并作决定。

## 4. 信息结构

### 收起：是否需要我

- 有待处理项：项目短名、明确事件文字和数量，如「API · 待审批 · +1」。
- 只有运行中项：小型静态信号和运行数量。不用持续旋转的动画制造紧迫感。
- 无活动项：可隐藏，或只保留悬停可展开的小标记，由偏好决定。
- 刘海中心为硬件排除区。左右内容各有自己的布局容器，不让长标题穿过中间。

### 展开：为什么需要我

从上到下固定包含：项目及来源、事件标题、必要的上下文、等待时间、主动作。事件详情不能挤掉主动作。只有用户主动展开时，才显示其他任务与历史。

### 历史：我是否已经看过

“已查看”仅表示用户进入了对应会话；“已处理”必须来自请求解除、任务恢复等状态证据。用户看了但没回答的提问继续留在待处理集合里。

建议后续设置页分为：提醒事件、声音与时段、显示器与位置、会话连接。设置界面不放会话正文。

## 5. 状态模型与文案

| 状态 | 展示文案 | 视觉信号 | 主动作 | 清除条件 |
|---|---|---|---|---|
| 运行中 | 正在处理 / 正在检查组件 | 中性小点，低权重 | 查看会话 | 收到新生命周期事件 |
| 本轮结束、未查看 | 本轮已结束 | 中性结果标记，不用成功勾 | 查看结果 | 用户查看后进入历史 |
| 等待审批 | 需要你确认 | 琥珀信号 + 审批文字 | 查看会话 | 请求明确解除或任务恢复 |
| 等待回答 | 有个问题需要你回答 | 蓝色信号 + 提问文字 | 查看问题 | 收到回答被接收/请求解除事件 |
| 运行终止 | 运行遇到问题 | 红色标记 + 简短原因 | 查看详情 | 用户查看；保留历史记录 |
| 已查看仍待处理 | 已查看 · 仍待确认 | 保留等待语义，降低新鲜提醒强度 | 返回会话 | 请求解除 |
| 用户主动中断 | 已停止 | 中性、静音 | 查看会话 | 用户查看或下一回合开始 |
| 连接不可用 | 暂时无法获取状态 | 灰色连接标记 | 检查连接 | 连接恢复 |

不能把 Stop 或“一段时间没输出”直接解释为任务成功。不能把单次工具报错立即提升成整轮失败，因为 Codex 可能继续修复。状态未知就明确显示未知，不显示绿色完成。

同一会话在「待审批 → 已查看 → 恢复运行」之间变化时保留同一对象身份，避免出现三个重复卡片。旧回合的完成通知不能盖住新回合的等待问题。

## 6. 注意力与多任务规则

1. 需要审批和需要回答优先，二者按等待时间排列；其次为确定终止的错误，再其次是本轮结束。
2. 正在阅读的对象不被新事件替换。新事件只改变待办数量或队列标记。
3. 同一会话同一回合同一请求重复到达时去重；恢复事件应解除旧等待状态。
4. 父任务仍在进行时，普通子任务结束默认不播报。子任务如果确实需要人介入，可以形成待处理项。
5. 用户正看着对应会话时可抑制普通结束播报；等待人处理仍保留视觉状态。精确会话焦点不可得时，不仅凭“终端在前台”就吞掉所有提醒。
6. 完成卡短暂展示后收起；待审批/提问保留可发现标记。语音一次，默认不无限循环催促。
7. 多条提醒在短时间内到达时合并成一句，如「有两个任务需要你处理」。不同时播放多段语音。

设计建议初始参数：完成卡展示 6 秒；多事件聚合窗口 3 秒；待处理项可在 60 秒后再提醒一次；用户暂缓可选 5 分钟。它们是待实测的设计默认值，不是现有产品能力承诺。

## 7. 系统语音设计

初始使用 macOS 系统中文声音；用户可试听、选择音色、调节语速和音量。语音和视觉提醒分别开关。

| 事件 | 固定短句 | 可选带项目名版本 |
|---|---|---|
| 本轮结束 | Codex 本轮已结束，请查看结果。 | Atlas 网站本轮已结束，请查看结果。 |
| 等待审批 | Codex 需要你确认，请查看会话。 | API 服务需要你确认。 |
| 等待回答 | Codex 有个问题需要你回答。 | 设计系统有个问题需要你回答。 |
| 确定终止 | Codex 运行遇到问题，请查看。 | API 服务运行遇到问题。 |
| 合并提醒 | 有多个任务需要你处理。 | 有两个任务需要你处理。 |

Claude Code 会话使用独立的 `claude-*` 音频，句首为“Claude”，如「Claude 需要确认。」；其余规则相同。

默认只播状态和可读项目名，不朗读代码、命令、完整问题、私有路径或最后一条长回复。固定短句可以由系统声音预生成音频；动态项目名可在后续原生版本使用系统语音接口生成。

优先级：人工介入 > 确认终止 > 本轮结束。新的高优先级事件可以等待当前短句结束后播放，低优先级重复项可被合并。音频故障不得阻断 Codex。

设置必须明确说明：暂停语音是否仍保留灵动岛；勿扰时段是否只抑制声音；恢复后是否补播。建议默认不补播过期的完成事件。锁屏时默认静音，解锁后显示仍待处理数量。

## 8. 三个方向的取舍

### A 伙伴接力：早期对照

保持 CodeIsland 黑色贴刘海外壳，当前会话的一只圆润小玩偶成为主角；项目、请求和等待时间紧邻角色，下方保留短交接线和主动作。角色引起注意，文字说明原因。

优势：日常占用小，小玩偶有存在感但不喧宾夺主，适合一边工作一边等待 Codex。代价：积压很多事件时需打开全部会话。

### B 会话伙伴岛：用户已选定

保留原项目纵向会话条目和状态标签；每行有对应姿态的圆润小玩偶，最需要介入的一行展开。原生版式细化中文排版、等待时间与主动作，不另造全新任务系统。

优势：迁移成本低，多任务扫读直接，可承接原有分支、工具和来源信息。代价：展开面积较大，小玩偶更像状态图标。

### C 项目泊位：历史对照，未采用

保持原项目顶部外壳与角色，展开为稳定的横向三泊位。每个项目各有自己的圆润小玩偶，选中项目的具体会话在底部共享详情条中显示。

优势：角色队列形成清楚的位置记忆，适合两到四个长期项目。代价：更多项目或同项目多会话需要溢出规则。

**最终采用 B。** 一行对应一个会话，项目是行内身份信息，不建立固定项目泊位或共享详情条。与参考 CodeIsland 保持同一列表结构；通过原创圆润伙伴、中文交接文案和明确的未读/待处理语义深化。

### 会话伙伴岛的完整规则

- **对象身份**：以来源与稳定会话标识识别行，回合和请求标识用于状态更新与去重。同一项目的桌面版与 CLI 分别列出；来源、任务标题仍相同时补充分支或短会话标识，不仅凭项目名跳转。
- **唯一主角与动作**：每次只展开一行，显示请求、等待时间和「查看会话」。点击其他行后在原位置展开，旧行收回摘要；不另开共享详情区。
- **初始排序**：审批/提问按等待时间排序，其次终止错误、本轮结束、运行中。同优先级保持稳定次序。打开期间不重新排序，不改变正在阅读的行、焦点或滚动位置；新事件更新原行或加入队列，下次重新打开再排序。
- **筛选与计数**：「全部」包含当前活动和未归档会话；「待处理」只包含未解除的审批与提问，包括已查看但未处理的请求。「待查看」是尚未查看的交接事件数，结束事件计入待查看但不计入待处理。
- **已查看不等于解除**：进入会话后保留等待状态，改为「仍待确认」或「仍待回答」，按钮为「返回会话」。收到明确解除/恢复事件才移出待处理。结束事件查看后进入历史。
- **新事件**：阅读期间不自动切换选中行。筛选隐藏的待处理项仍更新筛选计数；切换筛选时若当前行不可见，选择该筛选内最高优先级一行。
- **长列表**：默认 700px 宽；初始三行，只有一行展开。更多会话在列表区域滚动，工具栏与计数固定；底部显示剩余数量。展开行的主动作保持在可见区域；面板高度不超过显示器可用区域。
- **长标题与增大文字**：允许标题换行、行高增长；来源徽标可另起一行。按可用区域缩窄面板，先减少同时可见行数，不缩小字号。固定设计画板不代表已经实现此重排。
- **空与断连**：「待处理」为空时显示「暂时没有需要你处理的会话」及「查看全部」。没有活动会话时按偏好隐藏或留收起标记。连接不可用显示「暂时无法获取状态」与「检查连接」，不把任务标成完成。
- **收起**：保留刘海左右独立区，显示角色和待处理数量；审批/提问仍可发现。无刘海显示器使用独立悬浮条。

[会话伙伴岛关键场景](images/inbox-flows.png) 展示同项目多会话、新提问不打断阅读、已查看仍待确认与长列表入口。[声音设置](images/settings.png) 沿用既有设计，数值仍是设计建议。

### icon toy 的职责

按用户最新偏好，默认使用 Coucou 式圆润、柔和、有体积感的小玩偶，而不是像素角色。按最新蓝色重设计要求，正式稿使用原创「蓝色括号伙伴」：圆润蓝色头罩、冰蓝面罩、深蓝眼睛与一对可收拢或举起的软括号侧鳍。旧奶白方团、叶片胸标、腮红与脚已移除。以清楚的轮廓与表情适配 56px 会话列表，没有复制第三方角色图片。CodeIsland 的原有 Dex 资产作为经典皮肤参考保留，默认画面已全部换成圆润版本。

角色覆盖工作、等待确认、等待回答、待查看、休息和中断六个静态姿态。角色按来源区分：Codex 桌面版和 CLI 共用蓝色伙伴，再由来源标签区分；Claude Code 会话使用橙色小螃蟹，见下节。会话身份仍由项目名、来源、任务标题和短标识传达；角色帮助一眼分辨来源，不代替来源文字。

角色姿态与通知状态分层：休息不能单独证明完成；结束、错误和等待回答仍需可靠事件与清楚文案。本轮结束且未查看时使用淡紫色文档标记与托着结果卡的姿态，文案为“待查看”，避免暗示测试全部通过；查看规则见 [动效说明](MOTION.md#待查看2026-11-10)。

素材来源与许可见 [素材说明](assets/ATTRIBUTION.md)。收起时建议 24–28px，B 列表内 56px；历史 A 聚焦稿为 96px、C 泊位稿为 64px。24–28px 使用独立的 `toy-mini-*.svg` 光学校正版，扩大头罩与面罩，删去高光、阴影及光标，保留轮廓、眼睛与状态标签；不能简单缩小一段复杂动画。

角色网页动效已实现：工作双鳍轻动；等待时单次抬头举手后保持；休息时低频睁闭眼。浏览器后台、离屏与减少动态效果均有停止机制；锁屏等原生生命周期仍待接入。语音触发不依赖角色动画播放完成。详见 [动效说明](MOTION.md)。

### Claude Code 小螃蟹（2026-11-13）

用户要求 Claude Code 使用专属橙色和专属小螃蟹角色。「钳钳」是原创圆润螃蟹：橙色圆壳、两只眼柄、一对钳子和六条短腿，奶油色腹部与眼泡，深棕色眼睛。整只角色不使用蓝色，没有复制任何第三方角色或标志。

- **六态与伙伴一一对应**：工作时双钳在前、低头看提示符；休息合眼、钳子落地；待确认举起右钳；待回答侧身、钳子抬向头侧；待查看双钳捧住结果卡；运行失败皱眉、垂下双钳。状态角标与伙伴同形同位，待查看角标改用奶油色。
- **出现位置**：会话行和灵动岛提示按会话来源选择角色。收起区的角色属于决定汇总状态的会话：待处理时跟随等待最久的会话；运行中、待查看只有在相关会话全部来自 Claude Code 时才显示螃蟹，来源混合时保持蓝色伙伴，避免来回切换。设置、空状态与应用图标保持蓝色伙伴。
- **与状态色的关系**：橙色只用于螃蟹的身体，不用作状态信号。待确认仍使用琥珀色角标和文字；角标更浅、偏黄，带深色描边，位于壳体外侧。状态同时用文字和角标形状表达，不依赖颜色。
- **辅助功能**：角色本身不朗读；灵动岛提示的辅助功能名称包含来源。
- **尺寸**：24–28px 使用 `crab-mini-*` 光学校正版，放大圆壳和眼泡，去掉高光、阴影与提示符。实际尺寸见 [角色设计](ui/08-character.html)。

## 9. 几何、设备与可访问性

- 主视口为 1440×900，图中的产品浮层以可读桌面尺寸设计；对比画板中的外围标题属于设计说明，不属于应用。
- 真实实现从系统读取屏幕与刘海安全区域；190×32 只是设计参考，不硬编码为所有机型的尺寸。
- 展开内容从刘海下边缘开始；收起文字放两侧；无刘海屏幕使用独立悬浮条。
- 默认绑定当前选择的显示器，不随鼠标来回跳；全屏应用下的显示策略提供选项。
- 主动作至少 36px 高；图标动作命中区域至少 32×32px。正文目标 13–15px，标题 20–22px。
- 颜色不是唯一提示：同时使用文字与形状。正文与背景按 WCAG AA 对比度目标设计。
- 键盘：全局快捷键展开、方向键选择、Return 查看、Escape 收起。具体全局快捷键避免与用户已有快捷键冲突，首版可配置。
- 展开不得偷取当前输入焦点；只有用户主动操作后，键盘焦点进入面板。辅助功能名称读出项目、事件和等待时间。
- 增大文字时允许面板增高、标题换行，不能单纯缩小字体；关闭透明效果时换为实色。

## 10. 动效规格

角色层已在HTML源页面实现五态动效、播放控制和减少动态效果，见 [角色动效](MOTION.md)。下面的窗口与业务流程动效仍为后续实现规格；原生接入时继续沿用 CodeIsland 的暂停机制与状态模型。

| 时刻 | 动作 | 目的 |
|---|---|---|
| 收起到展开 | 220–280ms 高度与圆角过渡，内容轻淡入 | 让人知道卡片来自顶部同一对象 |
| 任务交接 | 角色首次抬头/跳一次；160ms 激活末端交接节点，随后停止 | 表达轮到人，避免反复催促 |
| 主按钮按下 | 90ms 轻微压暗，跳转后恢复 | 反馈操作已接收 |
| 新待办到达 | 数字与信号点短暂变化，不摇晃整个窗口 | 传递数量变化而不打断阅读 |

减少动态效果时取消位移与缩放，只保留短淡入或立即切换。动画不能延迟可点击状态。运行态没有持续闪光、扫光或粒子。

## 11. 接入架构建议与边界

建议采用「事件适配 → 标准事件 → 会话状态 → 提醒决策 → 灵动岛 / 系统语音 / 系统通知」的单向数据流。声音与视觉共享同一去重键，避免同一事件重复触发。

概念事件字段：source、sessionId、turnId、requestId、project、kind、occurredAt、target、summary、reliability。字段与错误策略需要在实际版本上验证。

- CLI 优先使用官方生命周期 Hooks；桌面版也以受支持的 Hooks/事件为优先入口，避免依赖窗口标题猜测。
- `PermissionRequest` 表示审批，不能代替提问事件；提问需要对应的工具/客户端事件适配。
- 桌面 app-server、rollout 或数据库读取只能作为按版本验证的适配方案，不把另一进程启动的 app-server 当成天然能订阅所有桌面会话。
- `notify` 与 Hooks 的输入不同，前者命令参数收到 JSON，后者 stdin 收到 JSON；需要分别解析。
- 保留用户当前 notify 接收者；新增功能优先用独立 Hooks，必要时使用保留原参数的串联适配器。
- 通知处理必须快速返回，不输出会改变审批结果的决定。语音在后台队列执行。
- 以后实现应直接在 CodeIsland 已有 SwiftUI/AppKit 结构内迭代，优先复用会话状态、MascotView 角色入口、AttentionPolicy 与 SoundManager；在角色入口增加圆润皮肤，并保留原 Dex 皮肤可选；本轮没有 fork 或构建原生工程。

新 Hooks 的信任应通过 Codex 官方界面完成。CLI 使用 `/hooks`，桌面版使用 Review hooks 或 Settings → Hooks。不能直接修改信任记录来绕过审核。

## 12. 进入实现前的验收清单

- 桌面和 CLI 各自验证：完成、审批、提问、主动中断、终止错误。
- 两个项目同一时间结束时不覆盖；同一项目两个会话不跳错。
- 请求已解决后，旧提醒及时解除；重启应用不补播已结束的历史消息。
- 语音无重叠，暂停/勿扰/锁屏行为符合设置。
- 有刘海、无刘海、外接屏、全屏和增大文字下都能看到主动作。
- 用户已有 notify 功能继续有效。

PNG与离线对比页用于静态视觉检查，HTML源页面可以验证角色动效及播放控制；真实生命周期接入、跳转成功率、声音、权限与原生动效手感仍需原生实现后测试。
